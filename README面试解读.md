## 一、「全栈微信小程序」是什么意思

**全栈** = 你自己一个人把前后端都写了。面试时可以这样说：

> 我独立开发了一个全栈项目，前端是小程序原生框架，后端是 Python FastAPI，数据库用的 MySQL，部署在微信云托管上。整个链路是我一个人搭建的。

## 二、「A 股财报数据」从哪来

你的数据不是瞎编的，是从**东方财富**和**同花顺**的公开接口抓的真实财报。

具体怎么抓的：用 Python 库 `akshare` 封装了东方财富的 HTTP 接口。面试时可以这样说：

> 通过 akshare 调用东方财富的报表接口，获取资产负债表、利润表、现金流量表。对于财务比率（ROE、毛利率这些），直接接入了同花顺的预计算接口——因为同花顺的算法比我更准，我不想重复造轮子。

**面试常见追问**：为什么不自己算比率？  
**回答**：同花顺是专业金融数据服务商，他们的算法经过市场验证，比自己算的准确。我只自己计算 FCF（自由现金流），因为这是一个简单减法，而且我需要按特定公式算。

## 三、「ETL 流水线」是什么

ETL = Extract（抓取）→ Transform（清洗）→ Load（入库）。就是把原始数据变成结构化数据存起来的过程。

你的 ETL 有**四层防御**，这是一个亮点：

| 层 | 做了什么 | 为什么 |
|----|---------|--------|
| 限速器 | 每次调用间隔 0.5-1.5 秒随机抖动 | 防止被东方财富封 IP |
| 重试机制 | 失败后自动重试 5 次，间隔越来越长 | 网络波动时不会丢数据 |
| 磁盘缓存 | 6 小时内不重复抓相同数据 | 减少 API 调用，加快响应 |
| 备用源 | 东方财富挂了换新浪财经 | 保证数据可用性 |

面试时可以这样说：

> 我设计了一个四层防御的 ETL 流水线：限速器防反爬、指数退避重试保数据完整、diskcache 缓存减重复调用、新浪财经做灾备。这保证了我的数据抓取在 5000 只股票全量同步时不会中断。

## 四、「SQLAlchemy ORM」是什么

ORM = Object Relational Mapping。简单说：**把数据库表映射成 Python 类，不用写 SQL 就能操作数据库**。

你的表设计：

```
stocks（股票表） ─── 一对多 ───▶ financial_statements（财报表） ─── 一对一 ───▶ financial_indicators（指标表）
```

面试时可以这样说：

> 我用了 SQLAlchemy ORM 来管理数据库模型。核心是一张 77 列的财报宽表，每行是一个报表期的完整数据，通过 symbol + report_date + report_type 做唯一约束，避免重复写入。财务指标单独一张表，和财报通过外键关联。

## 五、「DCF 估值模型」怎么算的

你的 DCF 是**两阶段**模型：

**阶段一**（明期 5 年）：假设每年 FCF 按 g1 增长率增长，然后折现到现在。  
公式：今年 FCF × (1+g1)^t / (1+WACC)^t，t=1到5，加起来。

**阶段二**（永续期）：第 5 年以后假设按较低的 g2 永远增长。  
公式：终值 = 第 5 年 FCF × (1+g2) / (WACC − g2)，这个终值还要再折现到今天。

面试时可以这样说：

> DCF 模型我用的是两阶段法——前 5 年逐期折现，之后用戈登增长模型算永续终值。用户能看到的每股内在价值 = 企业价值减净负债再除以总股本。

## 六、「WACC」怎么算的

WACC = 加权平均资本成本 = 股权成本 和 债务成本 的加权平均。

```
WACC = 股权占比 × 股权成本 + 负债占比 × 债务成本 × (1 − 税率)
```

具体：
- **股权成本** = 无风险利率(2.5%) + β(贝塔) × 市场风险溢价(5.5%)
- **债务成本** = 利息费用 ÷ 有息负债（从利润表/资产负债表取）
- **税率** = 所得税 ÷ 利润总额（从利润表取）

这些都是从真实财报里算出来的。面试时可以这样说：

> 我的 WACC 是自动计算的，不依赖用户输入。权益占比、债务成本、税率全从最新财报推导，β 值支持 15 个行业的默认参考值，用户也可以手动调整。

## 七、「筛选引擎」是怎么工作的

把用户的筛选条件翻译成 SQL 查询：

1. 用户选「ROE >= 15%」→ 翻译成 `WHERE roe >= 0.15`
2. 如果选了「连续 3 年」→ 用 SQL 窗口函数检查最近 3 份年报是否都满足
3. 多个条件 AND/OR 组合 → 用集合运算取交集/并集
4. 最后返回符合条件的股票列表

面试时可以这样说：

> 筛选引擎本质是一个 SQL 编译器——把 JSON 格式的用户条件翻译成 SQLAlchemy 查询。连续 N 年的逻辑我用窗口函数 `ROW_NUMBER() OVER PARTITION BY symbol` 来实现的，这样在一次查询里就能判断是否满足。

## 八、「MySQL 8.0 云开发托管」是什么

微信云开发提供了一个托管 MySQL 服务。你的后端跑在云托管的 Docker 容器里，数据库是独立的 MySQL 实例。

好处：**数据永久保存**。之前用 SQLite 存在容器本地，每次部署数据全丢。切换到 MySQL 后，部署不影响数据。

## 九、面试时可能被问的问题

**Q1：你的数据和 Wind/Bloomberg 比准不准？**

> 我直接调用了同花顺的预计算接口做指标数据，同花顺是国内最大的行情软件之一，数据经过市场验证。我还手动和美的集团 2025 年报做了交叉验证：营收对上了、净利润对上了、ROE 对上了、毛利率对上了。

**Q2：DCF 估值结果和真实股价差别大吗？**

> DCF 不是价格预测工具，它告诉你"给定这些假设，这只股票值多少"。默认参数的偏差大是正常的——每只股票的增长预期和风险不同，用户应该根据自己对公司的理解调整参数。我的设计思路是把这个框架搭好，让用户去调整。

**Q3：5000 只股票全量同步要多久？**

> 每只股票约需 10-15 秒（三张报表 + 指标），5000 只约 3-5 小时。我设计了分批同步机制，支持断点续传，中间失败不影响进度。

**Q4：怎么保证微信小程序能过审核？**

> 我的类目选的是「工具 → 信息查询」，不是金融投资建议。每个页面都有「仅供参考，不构成投资建议」的免责声明。数据全部来自公开财报，不涉及内幕信息或投资指导。

**Q5：这个项目最大的技术挑战是什么？**

> 数据准确性。财报数据源本身就有两套（东方财富和同花顺），单季度数据和累计数据容易混淆，我花了很多时间验证。比如美的集团 2025 年年报，我手动对比了营收、净利润、毛利率、ROE 等多个指标，确保和官方数据一致。

## 十、给面试官的一句话总结

> 这是一个独立开发的全栈 A 股财报分析工具，后端用 Python FastAPI 搭建，通过 ETL 流水线抓取 5000+ 只股票的真实公开财报，前端是微信原生小程序。核心功能包括多期财报对比、自定义指标选股、两阶段 DCF/DDM 估值模型。数据库用 MySQL 托管，部署在微信云平台上。
